## 测试环境问题

2026-08-09 | 环境搭建 | docker compose up 启动时报 `Pool overlaps`，无法创建网络 | `db-diagnostic-agent_diagnostic-net` 占用了 `172.20.0.0/16` 子网，与 JeePay compose 配置冲突 | `docker network rm` 删除冲突网络后重试 | "Docker 多项目共存时子网冲突是常见问题，我会先查 `docker network inspect` 定位冲突源，再决定是删除闲置网络还是修改项目子网"

2026-08-09 | 环境搭建 | MySQL 容器 unhealthy，启动日志报 `ERROR 1062: Duplicate entry` | `init.sql` 是全量库快照，`patch.sql` 又重复插入相同主键数据；同时 `patch.sql` 尝试对已有列重复 `ALTER TABLE ADD COLUMN` | 临时注释 docker-compose.yml 中 patch.sql 的挂载，只跑 init.sql（完成后恢复 compose 文件） | "init.sql 和 patch.sql 的设计冲突是典型的数据库迁移问题——init 是全量 dump 但包含后续补丁的数据，导致增量式 patch 重复执行时主键冲突。排查时我先 `docker logs` 定位到 SQL 错误行，再确认两个脚本的数据覆盖关系"

2026-08-09 | 环境搭建 | `unable to prepare context: path jeepay-ui not found` | UI 前端代码在独立仓库 `jeepay-ui`，默认路径指向 `../jeepay-ui`，本地未 clone | 启动时只指定 7 个后端容器，跳过 3 个 UI 前端（API 测试不需要前端页面） | "前端仓库独立部署时，我判断后端测试不需要页面，用 `docker compose up 具体服务名` 精确控制启动范围，减少了不必要的依赖"
