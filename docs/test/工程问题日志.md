# 工程问题日志

> 格式：日期 | 模块 | 问题描述 | 根因 | 解决方案 | 面试可讲

---

### 2026-08-12 | 回调模块 | conf/devCommons 配置覆盖测试配置导致 DB 连接失败 | Maven pom.xml 将 `../conf/devCommons` 打包为 `classpath:/config/application.yml`，Spring Boot 中 `config/` 目录优先级高于根目录，覆盖了 `src/test/resources/application.yml` 的 datasource（端口 13306→3306，密码 rootroot→123） | 将测试配置从 `src/test/resources/application.yml` 移到 `src/test/resources/config/application.yml`，同路径下测试 resources 优先级更高，全面覆盖所有配置项 | 展示对 Spring Boot 配置加载优先级的理解，以及排查 classpath 冲突的定位能力

### 2026-08-12 | 回调模块 | FastJson 序列化导致响应 body 断言失败 | 项目使用 FastJsonHttpMessageConverter 替代 Jackson，字符串 body 被序列化为 JSON 格式（带双引号），`equalTo("success")` 实际需要匹配 `"\"success\""` | 改用 `extract().body().asString()` + JUnit `assertEquals` 直接比对，可在断言 message 中说明原因 | 展示对不同 JSON 序列化框架的理解，以及 RestAssured matcher vs 手动提取的取舍

### 2026-08-12 | 回调模块 | 测试用例执行顺序导致数据污染 | JUnit5 默认不保证 @Test 方法执行顺序，CB-02 先于 CB-01 执行，将 ING 订单状态改为 3，导致 CB-01 断言期望 2 实际为 3 | 在测试类中添加 @BeforeEach 方法，用 JdbcTemplate 直接 SQL 重置 ING 订单状态 | 展示对测试隔离原则的理解：每个用例独立，不依赖执行顺序

### 2026-08-12 | 回调模块 | @MockBean 与 SpringBeansUtil.getBean() 兼容性 | ChannelNoticeController 通过 `SpringBeansUtil.getBean(ifCode + "ChannelNoticeService")` 动态查找渠道服务，而非 @Autowired 注入。Mockito @MockBean 替换了 Spring 容器中的实例，getBean 返回 mock 对象，因此 mock 生效 | 验证通过，无需额外配置。关键理解：@MockBean 操作的是 Spring 容器级别，无论注入方式（@Autowired 或 getBean），拿到的都是同一个替换后的实例 | 展示对 Spring 容器和 Mockito MockBean 机制的理解，能解释动态 Bean 查找场景下 mock 为何仍然生效
