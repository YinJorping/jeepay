## 测试环境问题

2026-08-09 | 环境搭建 | `docker compose up` 报 `Pool overlaps`，无法创建网络 | `db-diagnostic-agent_diagnostic-net` 占用 `172.20.0.0/16`，与 JeePay compose 子网冲突 | `docker network rm` 删除冲突网络后重试 | "多项目共存时子网冲突常见——先 `docker network inspect` 定位冲突源，再决定删闲置网络还是改项目子网"

2026-08-09 | 环境搭建 | MySQL 容器 unhealthy，日志报 `ERROR 1062: Duplicate entry` | `init.sql` 是全量快照但 `patch.sql` 重复插入相同主键 + 重复 `ALTER TABLE ADD COLUMN` | 临时注释 docker-compose.yml 中 patch.sql 挂载，只跑 init.sql | "典型数据库迁移冲突——init 含后续补丁数据，增量 patch 重复执行时主键冲突。先 `docker logs` 定位 SQL 错误行，确认两脚本覆盖关系"

2026-08-09 | 环境搭建 | `unable to prepare context: path jeepay-ui not found` | UI 前端在独立仓库，默认路径 `../jeepay-ui`，本地未 clone | `docker compose up 具体服务名` 只启 7 个后端容器，跳过 3 个前端 | "后端测试不需要页面，精确控制启动范围减少不必要依赖"

2026-08-10 | 支付模块 | Docker MySQL 密码错误 | docker-compose.yml 密码是 `rootroot`，测试配置误写 `root` | 核对 docker-compose.yml 后修正 | "不凭记忆写配置——先确认容器内实际密码再写测试配置"

2026-08-12 | 回调模块 | `Access denied for user 'root'@'localhost'`，Spring 测试连不上 DB | Maven 把 `conf/devCommons` 打包为 `classpath:/config/application.yml`，Spring Boot 中 `config/` 优先级高于根目录，覆盖测试配置（端口 13306→3306，密码 rootroot→123） | 测试配置移到 `src/test/resources/config/application.yml`，同路径下 test-classes 优先 | "Spring Boot 配置优先级：`config/` > 根目录。排查 classpath 冲突要确认 Maven resources 打包了哪些目录"

## 测试框架设计问题

2026-08-10 | 支付模块 | SignUtils 签名计算与服务端不一致 | SignUtils 遍历参数时 sign 字段也参与计算，服务端 `remove("sign")` 后再算 | 遍历时加 `&& !"sign".equals(key)` 跳过 | "签名验证核心——client 和 server 签名算法必须逐字段对齐，排查时对比两边的签名结果再反向定位代码差异"

2026-08-10 | 支付模块 | TestDataFactory 重新计算签名后 sign 被旧值覆盖 | 工厂方法多次操作同一 params map，移除 sign → 重新计算时旧引用污染 | 加 guard：若已存在 sign 字段则跳过 | "数据工厂封装要考虑参数可变性——多次操作同一 map 可能相互污染"

2026-08-10 | 支付模块 | PAY-014/018 无法触发预期错误，标记为死代码 | Controller 层 @NotBlank + queryMchApp 联合查询在业务逻辑前拦截，参数缺失由 Spring 框架处理而非业务代码 | 标记废弃并在用例清单注明理由 | "框架层校验先于业务层执行——不能只看接口文档，要读源码确认实际执行路径"

2026-08-10 | 支付模块 | PAY-016 禁用商户测试失败 | `queryMchApp` 是 mchNo + appId 联合查询，禁用商户用默认应用查不到 | 为 MCH-DISABLED 新建专属应用 APP-FOR-DISABLED | "联合查询场景——改单维度数据不够，关联维度也要有对应数据"

2026-08-12 | 回调模块 | 响应 body 断言 `equalTo("success")` 失败 | FastJsonHttpMessageConverter 将字符串序列化为 JSON 格式带双引号 `"success"` | 改用 `extract().body().asString()` + `assertEquals` | "不同 JSON 框架的序列化差异——FastJson 对裸字符串也会加 JSON 引号"
