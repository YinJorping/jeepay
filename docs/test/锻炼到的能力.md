## 6. 能理解客户流程

### 支付模块
- 统一下单 → MD5 签名 → 支付渠道 → 返回结果 的完整链路
- 订单 7 态：INIT(0) → ING(1) → SUCCESS(2)/FAIL(3)/CLOSED(6) → REFUND(5)

### 回调模块（最核心收获）
- 同步跳转（doReturn）vs 异步通知（doNotify）的触发方和流程差异
- 支付渠道 → JeePay 回调 → 订单状态更新 → 商户通知 的完整链路
- SQL WHERE state=1 守卫 = 幂等性 = 防重复/防非法状态转换
- doNotify 7 个分支：ifCode→查找Bean→解析参数→ID匹配→查订单→状态转换→后续处理
- 能画出完整流程图

### 退款模块（业务闭环第三步）
- 退款单 5 态状态机：INIT(0)→ING(1)→SUCCESS(2)/FAIL(3)，ING→CLOSED(4)，所有转换 CAS 守卫（`WHERE state=旧态`）
- 支付单退款三字段：refund_state（无/部分/全额）+ refund_amount（累计退款额）+ refund_times
- 核心校验：累计退款 + 本次 <= 支付金额（SQL 聚合 `sumSuccessRefundAmount` 防超退）
- 全额退款时支付单 state 2→5（已退款），部分退款 state 保持 2
- SQL 对账闭环：字段值 == 表 SUM 值，验证数据一致性
